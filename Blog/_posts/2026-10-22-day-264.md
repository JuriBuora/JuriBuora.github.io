# 🔄 Making Autonomous Reply Audits Explain What Actually Happened

I worked on the audit trail for autonomous WhatsApp replies. The important lesson was that a generated answer, a queued answer, a held answer, and a delivered answer are different security events.

# 🎯 Goal

The goal was to make every outcome distinguishable and replayable without creating a duplicate reply. If a reply was recorded but never left the bridge, a later replay needed to replace that incomplete outcome instead of producing a second message.

# 🛠 What I Did

The Hermes changes name autonomous-reply outcomes in the Telegram audit and preserve the inbound text associated with queued-lane replies. The bridge also records when a reply is held by policy, when it is replaced during replay, and when a message is actually eligible for delivery.

Other controls in the same period withheld system notices and third-person replies from WhatsApp chats, capped autonomous replies per group per hour, and required spoken content to pass the bridge policy before synthesis. These controls address different points in the path: content, rate, channel, and receipt.

# 🔗 Key Cybersecurity Connections

An audit log is useful only when its vocabulary matches the state machine. If “sent” means “model produced text,” an investigator may conclude that a user received something that was held or failed. That is an integrity problem in security evidence.

## 🔍 Investigation Questions

- Was content generated, queued, held, replaced, or delivered?
- Which policy caused a hold?
- Did replay consume an incomplete receipt or create a duplicate?
- Does the audit record identify the channel without exposing private content unnecessarily?

# ⚠ Challenges

Replay logic is especially easy to get wrong because the first attempt may have left durable state while producing no external effect. The safe behavior is to define which disposition is replaceable and to test that duplicate delivery does not occur.

# 📚 What I Learned

Auditability is not the same as logging more lines. It means defining state transitions precisely enough that a reviewer can tell what a person could actually have seen.

# 🧠 Reflection

In security work, the receipt is part of the control. A receipt that cannot distinguish “drafted” from “delivered” is a misleading control, even if it is technically present.
